Saran Penggunaan AI untuk Ekstraksi Data F-2.01 A

1. Mengapa AI (LLM) Sangat Tepat untuk Data Mentah Copas?

Teks hasil copy-paste dari portal rumah sakit, SIMRS, Puskesmas, atau chat WhatsApp tidak memiliki format yang seragam. Kadang nama ayah diawali "Tn.", ibu "Ny.", berat ditulis "3200 gr" atau "3.2 kg", dan tanggal ditulis format "Rabu Wage 18 Nov 2026". AI dapat memahami konteks semantik tersebut dan memetakannya langsung ke format baku Dukcapil.

2. Rekomendasi Model: Privasi vs Kecepatan

  • Opsi Terbaik untuk Privasi (Instansi / RS): Local AI via Ollama (Qwen 2.5 7B atau Llama 3.1 8B)
    Data NIK, No. KK, dan identitas keluarga adalah Personally Identifiable Information (PII) yang dilindungi UU No. 27 Tahun 2022 tentang Perlindungan Data Pribadi (UU PDP). Dengan model lokal Ollama, 100% komputasi AI berjalan di server internal tanpa ada 1 byte pun data yang keluar ke internet.
  • Opsi Terbaik untuk Akurasi & Kecepatan: Google Gemini 2.5 Flash
    Memiliki pemahaman Bahasa Indonesia yang luar biasa, latency sangat cepat (±1 detik), dan mendukung Structured JSON Outputs sehingga output terjamin valid sesuai skema formulir F-2.01 A.
  • Opsi Bawaan Tanpa Setup: Smart Regex Parser (Offline)
    Sistem ini telah dilengkapi mesin regex pintar yang dapat mendeteksi pola 16 digit NIK, No KK, tanggal, jam, dan berat secara otomatis tanpa butuh API key atau internet sama sekali.

3. Skema JSON Ekstraksi (Pydantic / Structured Output):

Sistem mengirimkan instruksi sistem agar AI menghasilkan JSON terstruktur tanpa markdown wrapper:

{
  "jenis_pelaporan": "Kelahiran" | "Kematian",
  "wilayah": { "provinsi": "...", "kabupaten_kota": "...", ... },
  "pelapor": { "nama": "...", "nik": "16-digit", "nomor_kk": "..." },
  "kelahiran": { "nama_bayi": "...", "jenis_kelamin": "...", ... }
}
